The email is trimmed too. On success Supabase emits `SIGNED_IN`, and the existing `onAuthStateChange` handler does the rest (session, profile). `signInWithEmail` is unchanged.
  - I added one line to the `AuthState` interface (around line 91), next to `signInWithEmail`. The contract needs it there; it sits outside Lane E's lines 16–70.
- **Code step in the sign-in dialog:**
  - `src/components/auth/AuthModal.tsx` is now step 1 (email). After a successful send it shows the new `src/components/auth/EmailCodeStep.tsx`.
  - Six digit boxes (`input-otp`, digits only) with `autoComplete="one-time-code"` and `inputMode="numeric"`, so iOS offers the code from Mail as a keyboard suggestion. It submits by itself on the sixth digit.
  - Errors: "That code isn't right." / "That code has expired. Send a new one." Supabase returns the **same** error for both (`otp_expired`, "Token has expired or is invalid"), so the app tells them apart by the time since the code was sent: more than 10 minutes (`EMAIL_CODE_TTL_MS`) means expired. This must match the expiry Lincoln sets in L11.
  - "Resend code" is disabled for 60 seconds, with a countdown ("Resend code in 42s"), then sends a new email and restarts the countdown. The 60 seconds matches Supabase's usual per-address email limit.
  - "Use a different email" goes back to step 1 with the address kept.
  - After a correct code, the dialog closes and the app goes to the saved `redirectUrl` (same origin only, then cleared), for example the protected route `RequireAuth` sent to `/`. The magic link already returns there through `emailRedirectTo` (review fix on #62).
  - Web text says "Enter it below, or tap the link in the email". Native text mentions only the code, because there are no deep links (by design).
  - Closing the dialog (X, Esc or outside click) now resets it to step 1. Before, it reopened on the "check your email" screen.
  - The button now says "Email me a code" instead of "Send Magic Link".
  - All strings in the dialog are now `auth.*` keys, translated in `en`, `es`, `pt` and `de`. That includes the "Account features unavailable" state, which was hard-coded English. The locale parity test passes with no new gaps.
