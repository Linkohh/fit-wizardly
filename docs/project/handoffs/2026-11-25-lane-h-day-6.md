## What changed
- **New dependency:** `@capacitor/local-notifications` 8.3.1. `npx cap sync` registered it in `android/app/capacitor.build.gradle`, `android/capacitor.settings.gradle` and `ios/App/CapApp-SPM/Package.swift`.
- **`useLocalNotifications()`** (`src/hooks/useLocalNotifications.ts`, contract #10): `requestPermission`, `scheduleRestEnd(at, body)` / `cancelRestEnd()` (id **1001**), `scheduleWorkoutReminders(days, hour, minute)` / `cancelWorkoutReminders()` (ids **2001–2007**, `2001 + weekday`, 0 = Sunday … 6 = Saturday; one weekly `schedule.on` per day). No-ops on the web; never throws.
  - Plugin loaded with a dynamic `import()` only on native, like `useHaptics.ts`.
  - **Guards against two v8.3 plugin behaviours** (from the plugin's README for 8.3.x, see "Plugin docs checked"): `schedule()` now asks for permission itself, so we only call it once permission is already granted (no surprise prompts, never a second ask); and Android exact alarms are the default and open the "Alarms & reminders" settings screen, so every notification passes `isExactNotification: false`.
  - Also exported: `ensureNotificationPermissionOnce()`. The first call shows the system prompt and records it under **`fitwizard-notif-asked`** in device storage (`appStorage`: a file in the app's data folder on native; ADR 11, not localStorage). Later calls never prompt. Concurrent calls share one prompt.
- **Rest timer** (`src/components/logging/RestTimer.tsx`, notification calls only): when a rest starts, the first rest ever asks for permission, then "Rest over. Time for your next set." is scheduled at `restTimerEndTime`. Adjust (+30 / −10) reschedules the same id; Skip and the timer ending cancel it. Finishing or discarding the workout cancels it; navigating away mid-rest keeps it.
- **Reminders block** (`src/components/notifications/WorkoutRemindersCard.tsx`, mounted in `src/pages/Profile.tsx` after Fitness Preferences, native only): "Remind me on training days" switch, Monday-first day chips (localised with `Intl`, `aria-pressed`, 44 px targets) defaulting to the plan's training days, and a time input (default 18:00). Every change saves and reschedules; off cancels. If permission isn't granted, the switch stays off and a toast says to turn notifications on in Settings.
  - Settings: my own `useReminderSettings` (`src/hooks/useReminderSettings.ts`), key **`fitwizard-reminders`** in `appStorage`, Zod-checked on read (malformed → defaults, never throws). Defaults from `daysPerWeek`: 3 → Mon/Wed/Fri, 4 → Mon/Tue/Thu/Fri, and so on. They're device settings: not synced, not in `clearLocalUserData`. No `preferencesStore` change, so nothing for Lane E.
- **Android manifest:** declares `POST_NOTIFICATIONS` explicitly (the plugin's manifest also adds it, with `RECEIVE_BOOT_COMPLETED` and `WAKE_LOCK`, so reminders survive a reboot) and **removes the plugin's `SCHEDULE_EXACT_ALARM`** with `tools:node="remove"`. We only use inexact alarms, so no special-access permission or Play declaration is needed.
- **Locales:** new `notifications.*` namespace (9 keys) in en, es, de, pt, inserted as text next to its alphabetical neighbour (after `notfound` in en/es, before `nutrition` in de/pt). Diff shows only the added lines.
- **Carried over, `allowRelative`:** removed from `validateRemoteEndpoint` in `src/lib/supabase.ts` (no callers since #80). Its test now checks that a relative path is rejected.
- **Carried over, splash:** no change, as agreed.

## Plugin docs checked
- **Verified** against the 8.3.1 package's own README and `android/src/main/AndroidManifest.xml` (the docs that ship with this exact version):
  - Android 13+ needs the `POST_NOTIFICATIONS` runtime prompt; the plugin's manifest declares it (and `SCHEDULE_EXACT_ALARM`, `RECEIVE_BOOT_COMPLETED`, `WAKE_LOCK`).
  - Exact alarms need `SCHEDULE_EXACT_ALARM` (Android 12+); `isExactNotification: false` schedules inexact outright with no permission.
  - From 8.3.0, `schedule()` requests notification permission if it isn't granted.
  - `schedule.on.weekday` uses 1 = Sunday … 7 = Saturday; `allowWhileIdle` lets a notification fire in Doze (at most once per 9 minutes per app).
- **Not verified:** the capacitorjs.com docs page (I relied on the package README, which is generated from the same source); real-device behaviour; whether iOS shows the banner while the app is in the foreground with the default `presentationOptions`.
