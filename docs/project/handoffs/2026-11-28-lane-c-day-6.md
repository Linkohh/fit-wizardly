### Source maps: steps for Lincoln (after L6)
1. **Sentry → Settings → Auth Tokens → Create New Token** (an organization token). Scopes: `project:releases` and `org:read` (Sentry's "Source Map Upload" preset). Note the org slug and project slug from the project's URL.
2. **Vercel → Project → Settings → Environment Variables.** Add these for **Production** and **Preview**, with no `VITE_` prefix so they never reach the browser:
   - `SENTRY_AUTH_TOKEN` = the token. Mark it **Sensitive**.
   - `SENTRY_ORG` = the org slug
   - `SENTRY_PROJECT` = the project slug

   Never commit the token or put it in `.env` files in the repo.
3. **Tell the board it's done.** The agent who picks it up then:
   - runs `npm i -D @sentry/vite-plugin`
   - in `vite.config.ts`, sets `build.sourcemap: 'hidden'` (maps are built but not referenced from the JS)
   - adds `sentryVitePlugin({ org: process.env.SENTRY_ORG, project: process.env.SENTRY_PROJECT, authToken: process.env.SENTRY_AUTH_TOKEN, release: { name: <the same value as __APP_VERSION__> }, sourcemaps: { filesToDeleteAfterUpload: ['dist/**/*.map'] }, disable: !process.env.SENTRY_AUTH_TOKEN })` as the **last** plugin

   The release name must equal the `release: __APP_VERSION__` that `src/lib/monitoring.ts` (line 138) sends, or Sentry won't match the maps. `disable` keeps local builds and CI without the token working. `filesToDeleteAfterUpload` stops `.map` files from being deployed or precached by the service worker.
4. **Check:** after a deploy, the Vercel build log shows the plugin uploading the maps, `https://<site>/assets/*.js.map` returns 404, and a test error in Sentry (with crash-report consent on) shows original file names and line numbers.
