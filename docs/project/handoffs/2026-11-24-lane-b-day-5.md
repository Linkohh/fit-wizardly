## What changed
- **Plan card placeholders (item 1):** `plan.workout_day.reps` and `plan.workout_day.rest` used `{{count}}`, but `WorkoutDayCard.tsx` passes `{ range }` and `{ seconds }`. Changed the strings to `{{range}} reps` and `{{seconds}}s rest` in `en.json` and `es.json`. de and pt have no `plan.workout_day.*` keys at all (already listed in `localeGaps.json`), so they fall back to the fixed English. New test `src/components/plan/WorkoutDayCard.test.tsx` renders `4 sets`, `6-12 reps`, `RIR 2` and `90s rest` and checks that no `{{` appears. It fails on the old strings.
- **Workout logger raw keys (item 2):** added a top-level `workout` namespace to `en.json` (just before `workoutLogger`), and to `de.json` and `pt.json` (just before `workoutResume`). It covers the 13 keys that `WorkoutLogger.tsx` and `RestTimer.tsx` use. In `es.json` I added the 3 missing keys (`difficulty_title`, `difficulty_desc`, `rest_timer`) to the end of its existing `workout` block. I translated de and pt instead of recording gaps, so `localeGaps.json` doesn't grow. New test `src/components/logging/workoutLoggerStrings.test.ts` reads every `t('workout.…')` key from both source files and checks that it resolves in all 4 locales without fallback. It fails without the locale change.
- **Empty "Full Body C" (item 3): reproduced on bdd59f5 and fixed** in `src/lib/planGenerator.ts`.
  - **Repro:** 3 days, chest only, intermediate + hypertrophy (the defaults), with bodyweight equipment. Day A got 7 sets, B got 7, and C got nothing. Advanced + strength failed the same way.
  - **Cause:** the per-day target was `ceil(weeklyCap / ceil(daysPerWeek / 2))`, which divides by 2 on a 3-day full body split. A and B used up the whole weekly cap.
  - **Fix:** divide the cap by the number of days that actually train the muscle. Full body 3 days with a cap of 14 now gives 5 + 5 + 4.
  - **A and B were identical:** the engine now counts how often each exercise was used this week and prefers less-used ones, after the existing compound-first rule. Days rotate through the catalog when it has enough exercises. (The test fixture has only 2 chest exercises, so the repro plan still repeats them. That is a catalog limit, not this bug.)
  - **Side effect, intended:** a push/pull/legs split (5–6 days) also uses the real frequency now: chest trains on 2 days, where the old maths assumed 3. Chest per Push day rises toward the cap. It stays within the weekly cap and the session set budget.
  - **Review fix (coordinator + review bot on `planGenerator.ts:516`):** with a single leg day, `ceil(cap / 1)` let the first leg muscle take the whole session budget (`floor(45 / 3) = 15`), so hamstrings and glutes got 0 sets on push/pull/legs. Each day now runs two passes. First, every muscle trained that day gets an equal share of the session (`floor(budget / dayMuscles)`). Second, muscles are topped up toward their per-day target with what's left. Exercises stay grouped by muscle. This also fixes the glutes-0 case that `preview_b` already had on 4 days (upper_lower), and a hamstrings-0 case on 3 days with mixed targets. Superset group numbers are now offset per allocation, so two separate supersets on one day no longer share group 1.
  - **Weekly sets, real catalog** (hypertrophy, intermediate, 45 min, all equipment). Format: `preview_b` → first #82 → now.

    | Targets | 3 days | 4 days | 5 days | 6 days |
    |---|---|---|---|---|
    | quads / hamstrings / glutes | 16/14/7 → 16/14/13 → **16/14/14** | 16/14/0 → 16/14/0 → **10/10/10** | 6/5/4 → 15/0/0 → **5/5/5** | 12/10/8 → 16/14/0 → **10/10/10** |
    | chest / upper back / lats / quads / hamstrings | 14/16/7/8/0 → 14/16/13/2/0 → **9/9/9/9/9** | 14/16/0/16/14 → same → **10/10/10/16/14** | 10/12/10/6/5 → 14/16/14/15/0 → **14/16/14/8/7** | 10/12/10/12/10 → 14/16/14/16/14 → **14/16/14/16/14** |

    5 days with legs only is 5/5/5 because that split has one 45-minute leg day (15 sets).
  - **Tests:** 2 new tests in `src/lib/__tests__/planGenerator.test.ts`. That is the existing file; the brief named `src/lib/planGenerator.test.ts`, which doesn't exist. One checks every level × goal combination for no empty day and the cap. The other checks rotation with a 3-exercise catalog. Both fail on the old engine. The review fix adds 2 more: every target muscle gets at least 1 set a week on 3, 4, 5 and 6 days with the real catalog (fails on `preview_b` and on the first #82), and no two supersets on one day share a group number.
- **Start Over dialog (item 4):** `WizardNavigation.tsx` now uses `t()` with English fallbacks for the button, aria-label, title, description, question, cancel, confirm and the toast. The new keys are in `wizard.start_over.*` in all 4 locales, after `wizard.navigation`. New test `src/components/wizard/WizardNavigation.test.tsx` covers the English flow and the Spanish strings.
- **Stepper accessible names (coordinator, DEBT-106):** `WizardStepper.tsx` step buttons no longer set an `aria-label`.
  - **Name mismatch:** the old `aria-label` used the long label ("Limitations"), which didn't match the short visible label ("Limits"), so axe flagged `label-content-name-mismatch`. The name now comes from the text on screen.
  - **Status text:** a screen-reader-only status ("(current)" or "(completed)") is appended. It uses the locale value as-is, so the old "Limitations ((current))" with doubled brackets is gone.
  - **Number circle:** marked `aria-hidden`, so the name doesn't start with "2".
  - **Checked in Chromium at desktop width:** the names read "Training Goal (completed)" and "Limitations (current)". The stepper renders only at `md` and wider.
  - **Tests:** new `src/components/wizard/WizardStepper.test.tsx` covers the names of current, completed and upcoming steps. It fails on the old markup. Lane D can now remove the `wizard:label-content-name-mismatch` allow-list entry.
