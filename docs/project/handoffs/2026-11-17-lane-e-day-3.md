## What changed
- **Saved on the device now**, each with a store version, load checks and the one-time localStorage move:
  - `nutritionStore` (v2): profile, targets, all daily logs, custom foods, favourite foods, saved meals, selected date. Load checks are in the new `src/stores/nutritionStore.persistence.ts`.
  - `readinessStore` (v1): check-ins. Malformed entries and ratings outside 1–5 are dropped.
  - `achievementStore` (v1): counters, streaks, weekly goal, badges. Unknown badges and negative counters are dropped. It still starts a fresh week on load.
  - `customExerciseStore` (v1): custom exercises.
- **Existing users' data moves over.** Readiness check-ins and achievements were previously in localStorage. They're now moved once into device storage, and the old copy is deleted only after a confirmed write. Tests cover this.
- **`src/lib/storage/clearLocalUserData.ts`** (contract #2). This erases every user-data store from the device and resets each one in memory: plans, nutrition, measurements, readiness, achievements, custom exercises, and the exercise preferences store (`fitwizard-preferences`). Stores load on demand so they stay out of the startup bundle. Lane F calls this for account deletion and guest erase.
- **`waitForHydration(store)`** (`src/lib/storage/hydration.ts`). The workout-completion path and the wizard now wait for achievements to finish loading before changing them. Without this, a store loaded on demand could be overwritten by its saved copy, losing the streak update.
- **Sign-out** (`authStore.ts`, `clearSensitiveStorage` only). Training data now **stays on the device**, and a toast says "Signed out. Your training data stays on this device." Until cloud sync exists (Day 6), clearing it would permanently delete data that exists nowhere else. Trainer, onboarding, wizard and wisdom keys are still cleared. Signing out shows one toast, not two: `signOut()` and the `SIGNED_OUT` event share a toast id.
- **`src/lib/translate.ts`** (new): `translate(key, fallback, options)` for stores and plain functions. Importing the app's i18n setup into `authStore` broke four test files that mock `react-i18next`, so this uses the `i18next` instance directly and falls back to English. `announceBadges.ts` uses it too.
- **`src/lib/storage/sanitize.ts`** (new): shared checks (`isRecord`, `isFiniteNumber`, `toValidDate`, `sanitizeList`, `sanitizeStringList`). `planStore.persistence.ts` now uses them.
- **`dateReviver`** now also restores `timestamp`, which meal entries use.
- **ADR 11** is in `docs/DECISIONS.md`, with a note that ADRs 5–10 live in the session log.
- **Locales:** `storage.kept_on_device` in en, es, de and pt, added as text insertions only.

## Review findings on PR #53 (automated reviewer): both confirmed and fixed
1. **A damaged achievements record could leave the wizard stuck on "Generating".** On a load error, zustand never sets `hasHydrated()` or calls `onFinishHydration`, so the old `waitForHydration` waited forever.
   - Fix: `waitForHydration(store, name)` now also settles when `hydrationTracking`/`markHydrated` records the store as finished. That happens even after an error. A safety timeout means it can never hang.
   - Test: corrupt JSON in storage, and the wait settles through the tracker with no timeout warning.
2. **Erasing could be undone.** When `clearLocalUserData` loaded a store that hadn't been opened yet, that store's saved data could still be loading, and would merge back in after the reset.
   - Fix: it now waits for each store to finish loading before resetting it.
   - Test: **checked that it fails without the fix** and passes with it.
- After the fixes: **861/861 tests**, lint 0 errors, typecheck clean, build passes, bundle 344.0 KB.
- **Contract change:** `waitForHydration` now takes the store's persist name as a second argument. Both callers are updated; no other lane uses it yet. `CONTRACTS.md` is updated.
