## What changed
- **Icons** (`public/*.png`): regenerated from `resources/icon.png` with `sharp` (scratch script, not committed): Lanczos resize, 256-colour palette PNG, no dithering. A side-by-side check showed no visible difference from the original. `ios/` and `android/` icons not touched.
- **Header logo:** new `public/brand/logo-header.webp` (160 × 160, alpha kept; the logo renders at about 56–64 CSS px × `scale-[1.22]` ≈ 78 px, so 160 px covers 2×). `src/components/Header.tsx`: changed only the `src`. `width`/`height` were already set. Deleted `public/lovable-uploads/` (nothing else referenced it).
- **`public/logo.png`:** still referenced by `index.html` (`og:image`, `twitter:image`) and the PWA `includeAssets`, so I shrank it in place to 512 px PNG instead of deleting it. Kept PNG because social crawlers handle WebP inconsistently.
- **`vite.config.ts` (PWA):**
  - Removed both `exercise-data/*.json` from `includeAssets`. Added `brand/logo-header.webp` (8 KB) so the header logo works offline on first launch.
  - Added `workbox.runtimeCaching`: `/exercise-data/*` → `StaleWhileRevalidate`, cache `exercise-data`, `maxEntries: 4`, as specified.
  - Manifest `description` → "Science-based workout plans, built around you." `orientation: 'portrait'` unchanged.
- **`src/lib/__tests__/exerciseOfflineAssets.test.ts`:** this test asserted the old behaviour (exercise JSON in the precache config), so it failed after the change. I rewrote it to assert the new contract: the catalogs are not in `includeAssets`, and the runtime-cache rule exists.

## Offline check (roadmap 0.7, step 6)
Scripted in Chromium (Playwright, scratch script) against `npm run build && npm run preview`, with onboarding and consent seeded the same way as `playwright/exercise-library.smoke.spec.ts`:
1. Online: load `/`, wait for the service worker, reload so it controls the page (`controller` = true), then open `/exercises`. `wger-snapshot.v1.json` served `200 fromServiceWorker=true`, and the `exercise-data` cache then held `/exercise-data/wger-snapshot.v1.json`. 30 exercise cards rendered.
2. Removed the app's own localStorage copies of exercise data (so only the service-worker cache could supply it), then set the context offline.
3. Offline: `/` loaded and the header WebP decoded (`naturalWidth` 160). `/exercises` showed the "Premium exercise library" heading and **30 exercise cards**. The snapshot was again served `200 fromServiceWorker=true`.

**Result: pass.** `legacy-exercises.v1.json` is only fetched on the fallback path, so it is cached the first time that path runs. A user who has never hit the fallback won't have it offline. This is expected with a runtime cache.
