## What changed
- **0.4 Launch languages** (`src/lib/i18n.ts`)
  - Each `AVAILABLE_LANGUAGES` entry now has `launchReady`: `en` and `es` true, `pt` and `de` false (decision D3 default).
  - New exports: `LAUNCH_LANGUAGES` (the filtered list), `isLaunchLanguage()`, `LanguageCode`, `LANGUAGE_STORAGE_KEY` (`'fitwizard-language'`, unchanged value).
  - `getInitialLanguage()` is now exported and takes `(storedLanguage, browserLanguage)` for testing; both default to the real `localStorage` and `navigator.language`. A saved or browser `de`/`pt` falls back to `en`. The `de` and `pt` resources stay loaded.
  - `changeLanguage()` wraps the `localStorage` write in try/catch so a blocked storage can't break switching.
  - New `src/lib/i18n.test.ts` covers the launch list, all the fallbacks, and that `changeLanguage` saves the choice.
- **Profile picker** (`src/pages/Profile.tsx`, language/units/theme block only)
  - The hardcoded `<SelectItem>` list (which offered French, with no locale behind it, and German) is now `LAUNCH_LANGUAGES.map(...)`.
  - Picking a language calls `changeLanguage()` from `@/lib/i18n`, so the choice is saved. If `i18n.language` isn't a launch language, the picker shows English.
  - The `EN`/`ES` code under the label is replaced by a translated description, "Used for every screen in the app." The label is linked to the trigger with `htmlFor`/`id`.
  - New `profile.*` keys in `en.json` and `es.json`: `app_settings`, `theme.{label,light,dark,system}`, `language.{label,description,placeholder}`, `units.{label,lbs,kg}`. The theme label used to read `header.theme.label`. It now uses `profile.theme.label`.
  - New `src/pages/Profile.language.test.tsx` uses the real i18n instance: the picker lists English and Español only; choosing Español stores `es`; after a simulated reload, the block reads Idioma / Tema / Unidad de peso / Ajustes de la app.
  - `src/pages/Profile.test.tsx` gets a `@/lib/i18n` mock. It already mocks `react-i18next` without `initReactI18next`, so importing the real module would crash.
  - Smoke test (dev server, Playwright, 390×844): the picker shows `English`, `Español`. Choosing Español stores `es`. After a reload the page shows "Idioma". Setting storage to `de` and reloading shows English.
- **`pt.json` duplicate `wizard` key merged as text.** The first block (`title`, `steps.*`, `navigation.*`, `progress`) moved to the top of the second block, and the first block was deleted. Every key path from both copies was compared with a duplicate-preserving reader: 232 before, 232 after, the same set, no collisions. `git diff` shows only the move.
  - The 11 restored keys (`wizard.title`, `wizard.progress`, `wizard.steps.*`, `wizard.navigation.*`) are removed from the `pt` list in `src/test/fixtures/localeGaps.json`, because they're translated again. The 11 new `profile.*` keys are added to the `de` and `pt` gap lists, since those languages aren't launch-ready. The fixture has no duplicate keys and round-trips byte for byte, so it was rewritten as JSON. No locale file went through a parser.
- **`src/components/LanguageSelector.tsx` deleted.** Nothing imported it, and there was no test or barrel export.
