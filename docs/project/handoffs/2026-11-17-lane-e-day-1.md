## What changed
- **`src/lib/storage/appStorage.ts`** (new): async Zustand `StateStorage` that picks a backend once, in this order:
  - IndexedDB through `idb-keyval`, in its own database `fitwizard` / `kv`, probed once at start
  - Capacitor Filesystem (`Directory.Data/stores/<name>.json`) on native, loaded with a dynamic `import()` so the web bundle doesn't carry it
  - an in-memory fallback if neither works
  
  Reads and writes never throw: failures are logged and reads return `null`.

  It also exports:
  - `dateReviver`: restores `Date` for `startedAt`, `completedAt`, `achievedAt`, `createdAt` and `updatedAt`, but only for full ISO date-time strings
  - `requestPersistentStorage()`: asks the browser once, then only checks the current state; does nothing on native
  - `toStorageFileName()`, `getStorageBackendKind()`, `resetAppStorageForTests()`
- **`src/lib/storage/hydration.ts`** (new): a registry of persisted stores. Stores opt in with `...hydrationTracking(name)` in their `persist()` options. It has a 3-second safety timeout that logs which stores were still loading, so a broken store can't freeze the app.
- **`src/hooks/useStoresHydrated.ts`** (new): `useStoresHydrated()`.
- **`src/components/HydrationGate.tsx`** (new): shows the existing `LoadingScreen` (from `src/components/ui/loading-screen`) until registered stores have hydrated. It **gates only the first render**: once open, it stays open, so a store that registers later from a lazy page never brings back the loading screen.
- **`src/main.tsx`:** `<App />` is wrapped in `<HydrationGate>`.
- **Dependencies:** `idb-keyval@^6.3.0`, `@capacitor/filesystem@^8.1.5` (peer `@capacitor/core >=8`, which matches), and dev-only `fake-indexeddb@^6.2.8`.
- **Tests:** `src/lib/storage/appStorage.test.ts` (15 tests) and `src/components/HydrationGate.test.tsx` (7 tests).

**No user-visible change yet.** No store uses `appStorage` until Day 2, so with nothing registered the gate opens immediately.
