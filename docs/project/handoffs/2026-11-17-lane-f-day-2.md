## What changed
- **`supabase/migrations/008_policy_fixes.sql`** (new, re-runnable):
  1. **Recursion:** `is_circle_member(uuid)` as specified, plus `is_circle_admin(uuid)` (same shape, `role = 'admin'`). Both `SECURITY DEFINER`, `search_path = public`, revoked from `PUBLIC` **and `anon`** (Supabase's default privileges grant anon directly), granted to `authenticated` and `service_role`. Every 001/003/006 policy that repeated the membership subquery now uses them: `circles`, `circle_members`, `circle_activities`, `circle_challenges`, `activity_reactions`, `activity_comments`, `circle_posts`, `challenge_participants`.
  2. **Forgeable gamification:** dropped the client INSERT/UPDATE policies on `user_streaks` and INSERT on `exercise_badges` (SELECT-own stays). `challenge_participants`: dropped the client UPDATE policy **and** added trigger `trg_protect_challenge_score`. For `anon`/`authenticated`, an insert starts at 0 and an update keeps the old score. Without the trigger, a client could still join with `score = 999`.
  3. **Profiles:** dropped `USING (true)`. Added "Users can read their own profile" and "Signed-in users can read profiles of people they share a circle with" (`shares_circle_with(uuid)`, `SECURITY DEFINER`). anon gets nothing. UPDATE now also has `WITH CHECK`.
  4. **DELETE policies and cascades:** `circles` (admins only), `circle_activities` (author or admin), `circle_challenges` (creator or admin), `profiles` (own row). Foreign keys to `profiles` that were NO ACTION now are: `circle_activities.user_id` CASCADE; `circles.created_by`, `circle_challenges.created_by` and `circle_challenges.winner_id` SET NULL. Before this, **deleting any user who had created a circle failed**, which would also have broken Day 3's delete-account function.
  5. Every circle and profile policy is now `TO authenticated`.
- **`supabase/tests/008_policy_fixes.test.sql`** (new): structure checks (definer helpers, no policy with `FROM`/`JOIN circle_members`, `TO authenticated`, no client write policies on streaks or badges, every user FK is CASCADE or SET NULL, DELETE policies present), plus the behaviour checks listed in the brief and a few more (see "Verified locally" in `docs/SUPABASE_MIGRATIONS.md`).

## Decisions beyond the brief (flag if you disagree)
- **Added `is_circle_admin()`** next to `is_circle_member()`, for the admin UPDATE/DELETE checks on `circles` and the admin-delete branches.
- **`circles` SELECT also allows `created_by = auth.uid()`.** Without it, `createCircle()` in `src/stores/circles/membership.ts` can't read back a new private circle (`insert().select()`). Its admin self-join (006's INSERT check) also fails, because the creator isn't a member yet. This was already broken before 008, and the test covers it.
- **`circles` INSERT now requires `auth.uid() = created_by`** (was `auth.uid() IS NOT NULL`). The client already sends `created_by: user.id`.
- **Public circles are no longer visible to anon.** Policies are `TO authenticated` so that anon never calls the revoked helpers, which would raise "permission denied" instead of returning no rows.
