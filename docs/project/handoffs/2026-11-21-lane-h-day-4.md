## What changed
- **Sessions last (2.2, decision D2).** New `src/lib/authSessionStorage.ts`, used by `src/lib/supabase.ts`:
  - Native: `@capacitor/preferences` (new dependency, `^8.0.1`), loaded lazily. In the build it's a 0.5 KB chunk of its own.
  - Web: `window.localStorage`. **Review fix:** if localStorage can't be written (site data blocked, or it throws), the session stays in `sessionStorage` for the tab, and nothing is moved. If a write still fails, the session is kept in memory for the page instead of being lost.
  - The `sessionStorage` choice is gone. The storage key is now passed explicitly (`sb-<project ref>-auth-token`), which is the same value Supabase used by default, so existing keys don't change.
  - **One-time move:** on first use, any `sessionStorage` entry under that key (the token plus its `-user` and `-code-verifier` companions) is copied to the new storage, unless the new storage already has one. The old copy is removed only after the new storage reads it back from durable storage (never from the in-memory fallback), so a failed write can't lose the session. Every storage call waits for this, so Supabase's first read at start-up already sees the moved session. Other `sessionStorage` keys (for example `pendingInviteCode`) are left alone.
- **Sign-out confirmed:** `supabase.auth.signOut()` removes the token, `-user` and `-code-verifier` from the new storage (`_removeSession` in auth-js). This is tested with a real Supabase client on both web and native (Preferences mocked). `authStore.signOut` didn't need changing for this.
- **`signOut({ quiet: true })`** (requested by Lane F): clears the same keys but skips the "Signed out. Your training data stays on this device." toast, including the one the `SIGNED_OUT` event would show. Plain `signOut()` is unchanged.
- **Sync after restart:** `initialize()` already sets `user` from `getSession()` exactly as `SIGNED_IN` does. The new `src/App.session-restore-sync.test.tsx` renders the real `App` with the real `authStore` and checks that a restored session calls `startSync('user-restored')`, and that no session doesn't start it.
- **ADR 12** appended to `docs/DECISIONS.md`.
- **Carried over, DEBT-079:** `EmailCodeStep` (and `input-otp`) is now `React.lazy` in `AuthModal.tsx`. It's prefetched when the user taps "Email me a code", so there's normally no spinner. It builds as its own chunk (13.7 KB, 5.4 KB gzip) and is out of the startup bundle.
- **Carried over, DEBT-085:** send errors are translated. New `src/components/auth/sendErrorKey.ts` maps Supabase's `code` and `status` to four `auth.send_error_*` keys (rate limit, invalid address, offline, generic), used for both send and resend. New keys are inside the existing `auth` namespace in all four locales, inserted as text after `auth.close`.
- `npx cap sync` registered the plugin in `android/app/capacitor.build.gradle`, `android/capacitor.settings.gradle` and `ios/App/CapApp-SPM/Package.swift`.
- Tests: `src/lib/authSessionStorage.test.ts` (localStorage blocked keeps the old and the new session in the tab; no web storage keeps it in memory; a failing localStorage or Preferences write keeps the old copy; web uses localStorage; native uses Preferences; the move runs once, doesn't overwrite, works on native; real-client restore, restore of an old `sessionStorage` session, and sign-out on web and native), `sendErrorKey.test.ts`, two `AuthModal.test.tsx` cases (translated rate-limit and generic errors), and an `authStore.test.ts` case for the quiet sign-out.
