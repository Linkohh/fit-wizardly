## What changed
- `src/App.tsx`
  - The `/clients`, `/clients/:clientId`, `/templates` and `/revenue` routes are registered only when `isFeatureEnabled('coach')`. The `/circles` tree (index, `join/:inviteCode`, `:circleId/*`) is registered only when `isFeatureEnabled('circles')`. When a flag is off, those URLs fall through to the existing `*` route and show `NotFound`.
  - The `pendingInviteCode` effect does nothing while circles is off. It leaves the stored code in place, so the invite still works if the flag is turned on later.
- `src/components/header/mobile-drawer-model.ts`: `buildMobileNavItems` takes an optional `features: { circles, coach }`, which defaults to the build-time flags through the new `getMobileNavFeatures()`. It leaves out `/circles` when circles is off, and returns no trainer rows when coach is off, even if `isTrainerMode` is true.
- `src/components/Header.tsx`: `isTrainerEnabled` now also requires the coach flag. This gates the desktop nav (which is built from the same model), the drawer's "Coach Tools" section and the "Coach Mode" profile badge. The "Coach Mode" switch is hidden both in the desktop profile dropdown and in the drawer footer cluster. The trainer dropdown has no other entries besides the switch.
- `src/components/CommandPalette.tsx`: the Circles command and the "circles" group are hidden when circles is off. There are no coach commands in the palette.
- `src/pages/NotFound.tsx`: the `/circles` quick link is hidden when circles is off.
- `src/contexts/navigation-direction-context.tsx`: **not changed**. `NAV_ORDER` only sets the direction of the page animation, and nothing renders a link from it.
- Tests
  - New: `src/App.feature-flags.test.tsx` covers all 7 paths with the flags off (NotFound) and on (the page), plus the invite effect in both states and each flag on its own.
  - New: `src/components/CommandPalette.feature-flags.test.tsx` and `src/pages/NotFound.feature-flags.test.tsx` cover both states.
  - Updated: `src/App.auth-routing.test.tsx` and `src/components/__tests__/Header.mobile-menu-layout.test.tsx` turn both flags on in `beforeEach` and unstub them in `afterEach`. The Header test gains one case per flag state.
  - Updated: `src/components/__tests__/mobile-drawer-model.test.ts` covers both flags on, both off, each flag on its own, and the env default.

## Contracts
- Used: #1 feature flags, exactly as published. No env variables are read directly.
- **Deviation from the brief, not from the contract:** the brief says to read the flags "once at module level". I read them on render instead (`isFeatureEnabled()` inside the component). The brief also asks tests to use `vi.stubEnv` in `beforeEach`, but a value read at module level is fixed when the test file's hoisted imports run, so that pattern would not work. The lookup is a single env read, and the flags are still build-time values in production. If you want module-level constants, tests would need `vi.resetModules()` plus a dynamic `import('./App')`.
- Provided: nothing new. `MobileNavFeatures` and `getMobileNavFeatures()` are exported from `mobile-drawer-model.ts` for Lane C's own use.
