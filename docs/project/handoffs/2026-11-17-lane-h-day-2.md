- **DEBT-054 (native wger):** `service.ts` no longer branches on `isNativeApp()`. Both platforms call `apiUrl('/api/proxy-wger?url=…')`, so native no longer relies on wger's CORS headers now that CapacitorHttp is gone.
- **DEBT-055 (one wger path), decision: always through the proxy.** `WgerAdapter.search` now calls `apiUrl('/api/proxy-wger?url=…')` instead of `https://wger.de` directly. Why: one host allowlist and one rate limit, no CORS dependency on native, and it works the same on web and native. The cost is one extra hop for live search; both cached search and the snapshot already absorb most traffic. New `src/lib/services/api/exerciseApiAdapter.test.ts` pins both paths.
- **`api/*` hardening (2.3):** new `api/_lib/guard.ts` (the leading `_` keeps Vercel from deploying it as a function), used by all three functions.
  - **CORS allowlist:** `ALLOWED_ORIGINS` (comma-separated) plus the deployment's own `VERCEL_URL`, `VERCEL_BRANCH_URL` and `VERCEL_PROJECT_PRODUCTION_URL` (so production and beta previews work before L3 is settled), plus `capacitor://localhost` and `https://localhost`. A request from any other origin gets a **403** `{ error: 'Origin not allowed', code: 'ORIGIN_NOT_ALLOWED' }`. Requests with no `Origin` header pass (same-origin GETs). Allowed origins are echoed back with `Vary: Origin`; `Access-Control-Allow-Credentials` is gone (nothing sends credentials).
  - Preflight `OPTIONS` → 204; methods other than GET → 405.
  - **Rate limit:** a per-IP fixed window, 60 requests a minute, held in memory → **429** with `Retry-After`. The IP comes from `x-real-ip`, then the first `x-forwarded-for` entry, then the socket. The table is capped at 10,000 clients. **This is per function instance and best-effort**: a cold start or a second instance starts with an empty table. Vercel firewall rate-limit rules are the long-term fix.
  - The shared handlers in `src/lib/…Endpoint.ts` still set `Access-Control-Allow-Origin: *`, because the Vite dev server uses them too and those files aren't Lane H's. The Vercel wrappers pass them a response wrapped by `withGuardedCors()`, which drops any `Access-Control-*` header they try to set, so `*` never reaches production.
  - **`proxy-wger.ts`** now matches the dev proxy in `vite.config.ts`: `https:` required, `redirect: 'error'` (was `'manual'`), and the same host allowlist (`wger.de`, `www.wger.de`). A malformed `url` → 400. When the fetch throws, the response is a generic **502** `Upstream request failed` (the detail goes to `console.error`, not to the client).
  - Tests: `api/_lib/guard.test.ts` (allowed and blocked origins, no-Origin, preflight, 405, the 429 and window reset, IP parsing, the CORS wrapper) and rewritten `api/*.test.ts` (each function: blocked origin, plus the 429 for motivation-quote and proxy-wger; proxy-wger: http, look-alike host, malformed URL, generic error). Shared test helper: `api/_lib/testResponse.ts`.
