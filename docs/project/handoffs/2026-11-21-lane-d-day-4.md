## What changed

### 3.5: lifter loop (`playwright/lifter-loop.spec.ts`, new)
Runs as a guest with no Supabase, chromium only (`test.skip` for other browsers). It uses roles and labels throughout. The steps:
1. Fresh context. Accept consent, go through onboarding (name, one interest).
2. Wizard:
   - goal: Strength (clicks the card heading; the radio input is visually hidden)
   - limitations: none
   - equipment: the **Full Gym** preset
   - muscles: the **muscle search** ("chest" → Pectoralis Major), not pixel clicks
   - schedule: defaults
   - then **Generate Plan**
3. Plan shows day 1 (`Full Body A`). Start the workout, skip readiness.
4. Log two sets (40 × 10 and 42.5 × 8, both at RIR 3 set from the keyboard on the slider). The test waits until both sets are in IndexedDB (`fitwizard` / `kv` → `fitwizard-plans`, contract #2) rather than sleeping.
5. **Reload partway through the workout.** The page still shows the workout, IndexedDB still has both sets, and set 3 is prefilled from saved set 2. Plan still shows the plan.
6. `storageState({ indexedDB: true })`, close the context, open a new one on that state. The plan and both saved sets are still there.

Two parts are written in full but marked `test.fixme`. I ran each one without `fixme` to check it fails for the stated reason:
- **Finish, rate, History after a reload:** fails waiting for a "Finish workout" button, because none exists (DEBT-094). Persistence (contract #2) has merged; this is blocked by the missing control, not by storage.
- **Saved sets show as completed after a reload:** fails because `WorkoutLogger` doesn't pass `loggedSet` (DEBT-095). With that one-line change made locally (not committed), it **passes**, and the main test still passes.

I didn't assert the sync row (demo mode). Hydration waits use the visible UI that `HydrationGate` reveals (contract #2) instead of a timer.

### `src/components/logging/SetLogger.tsx`
- **Bug fix (HIGH):** each set copied the *previous* set's `completed` flag (`previousSet` is the set before it, passed in for prefilling). Logging set 1 locked set 2 with set 1's numbers, so set 2 could never be logged; only odd-numbered sets worked. A set now starts unlogged. It still prefills weight, reps and effort from the previous set until it is logged, and keeps its own values afterwards.
- **Accessible names:**
  - each set is `role="group"` named "Set N"
  - the weight and reps inputs are linked to their labels (`htmlFor`/`id`), with `inputMode` for mobile keyboards
  - the ± buttons are "Decrease/Increase weight/reps"
  - the RIR/RPE toggle has `aria-pressed`
  - the done tick is `img` "Set completed"
- **New optional prop `loggedSet?: SetLog`** (this set's own saved log). When it's completed, the set shows as done with its values. When it changes to an unlogged set, the set unlocks.
  - This fixes two problems once `WorkoutLogger` passes it (DEBT-095): saved sets look unlogged after a reload, and moving to the next exercise leaves the reused set rows locked (they're keyed by index).
  - Without the prop, behaviour is the same as above.
- `src/components/logging/__tests__/SetLogger.test.tsx` (new): 5 tests covering names, the prefill-without-locking fix (it fails on the old code), keeping logged values, and both `loggedSet` cases.
