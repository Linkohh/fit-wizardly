## What changed

### 3.5: lifter loop (`playwright/lifter-loop.spec.ts`, new)
Runs as a guest with no Supabase, on chromium only (`test.skip` for other browsers). It uses roles and labels throughout. One test covers the whole loop:
1. Fresh context. Accept consent, then onboarding (name, one interest). Since #76, onboarding lands on wizard **step 2** with the goal filled in from the interest.
2. Wizard:
   - Back to step 1 through the stepper. The goal is pre-filled as Muscle Growth; choose **Strength**.
   - Limitations: none.
   - Equipment: the **Full Gym** preset.
   - Muscles: the **muscle search** ("chest" → Pectoralis Major), not pixel clicks.
   - Schedule: defaults. Then **Generate Plan**.
3. Plan shows day 1 (`Full Body A`). Start the workout and skip readiness.
4. Log two sets (40 × 10 and 42.5 × 8). Both are at RIR 3, set from the keyboard on the slider. The test waits until both sets are in IndexedDB (`fitwizard` / `kv` → `fitwizard-plans`, contract #2) rather than sleeping.
5. **Reload partway through.** Both saved sets show as done with their values. Set 3 is next, prefilled from set 2.
6. **Finish workout** → "How was the workout?" → **Just Right** → summary → **Done** → History shows the workout. The test also waits for the log in IndexedDB.
7. **Reload.** History still shows the workout, and Plan still shows the plan.
8. Save the storage state (`storageState({ indexedDB: true })`), close the context, and open a new one on that state. History, the saved log and the plan are all still there.

I didn't assert the sync row (demo mode). Hydration is waited for through the UI that `HydrationGate` reveals (contract #2).

### `src/components/logging/SetLogger.tsx`
- **Bug fix (HIGH):** each set copied the *previous* set's `completed` flag. `previousSet` is the set before it, passed in only for prefilling. Logging set 1 locked set 2 with set 1's numbers, so only odd-numbered sets could be logged.
  - A set now starts unlogged.
  - It prefills weight, reps and effort from the previous set until it is logged.
  - Once logged, it keeps its own values.
- **New optional prop `loggedSet?: SetLog`**, the set's own saved log:
  - a completed log shows the set as done, with its values
  - a change to an unlogged log unlocks the row
  - a saved log takes priority over prefilling when both effects run in the same render (found by the new exercise-switch test)
- **Accessible names:**
  - each set is `role="group"` named "Set N"
  - the weight and reps inputs are linked to their labels, with `inputMode` set for mobile keyboards
  - the ± buttons are named "Decrease/Increase weight/reps"
  - the RIR/RPE toggle has `aria-pressed`
  - the done tick is `img` "Set completed"

### `src/components/logging/WorkoutLogger.tsx` (allowed exception, assigned on 2026-11-22)
- **DEBT-095:** passes `loggedSet={set}` to each `SetLogger`. After a reload, saved sets show as done. Moving to the next exercise unlocks its rows, and going back shows the logged ones.

  - It's disabled until at least one set is logged.

- The previous and next exercise buttons now have names ("Previous exercise" / "Next exercise"). That's part of DEBT-098, and the unit test needed them.
- Strings: a new `workoutLogger` namespace (`finish`, `previous_exercise`, `next_exercise`).
  - en and es are filled in.
