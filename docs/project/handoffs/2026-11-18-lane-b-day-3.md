## What changed
- **3.6a Empty states.** Each one is a single sentence and a single button, built from the existing `Card` and `Button` components with semantic tokens.
  - New `src/components/empty-states/WorkoutEmptyState.tsx`, shared by History and Analytics. It reads `planStore.currentPlan`. With a plan, the button is **Start today's workout** → `/plan`. Without one, it's **Create a plan** → `/wizard`.
  - `src/pages/History.tsx`: with no workout logs it shows "Your finished workouts will show up here." This replaces the faded "No History Yet" block, which always linked to `/plan`, even with no plan.
  - `src/pages/Analytics.tsx`: with fewer than 2 workout logs (`MIN_WORKOUTS_FOR_TRENDS`), the tabs are replaced by "Log two workouts to see your trends." The page title stays. The tabs block was only re-indented inside the new conditional.
  - `src/pages/Nutrition.tsx`: with no meals for the day, "Today's Log" shows "Nothing logged today." and a **Log a meal** button. On another date it reads "Nothing logged on this day." The button calls the food logger's `openLogger()` and scrolls it into view.
- **Review fix (agreed exception in an unowned file):** `src/components/nutrition/FoodLogger.tsx` now uses `forwardRef` and exposes a `FoodLoggerHandle` with `openLogger()`, which only ever opens the logger. If it's already open, the call does nothing, so the user's tab and search are kept.
  - The coordinator approved this one-time exception during the #68 review. The file has no owning lane in the ownership table.
  - The first version clicked the logger's first `<button>`. Once the logger was open, that button was the close "X", so a second press of "Log a meal" closed it. The automated review found this.
  - New test: pressing "Log a meal" twice leaves the logger open. It fails against the old approach.
- **Loading states.** Through `useStoresHydrated()` (contract #2, merged), History and Analytics show `PlanSkeleton` and Nutrition shows `NutritionSkeleton` until stores have hydrated. `HydrationGate` already holds the first render, so in practice users will rarely see these.
- **Locale keys** (`en.json`, `es.json`, edited as text): `emptyStates.start_workout`, `emptyStates.create_plan`, `emptyStates.history.message`, `emptyStates.analytics.message`, `emptyStates.nutrition.{message,message_other_day,action}`.
  - The same 7 keys are added to the `de` and `pt` lists in `src/test/fixtures/localeGaps.json`, sorted. Those languages aren't launch-ready; Day 2 did the same with `profile.*`. `es` has no new gaps.
