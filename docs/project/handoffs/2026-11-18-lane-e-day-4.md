## What changed
- **`src/lib/sync/`** (new, contract #5):
  - `types.ts`: `SyncCollection`, `SyncRow`, `SyncResult`, `SyncStatus`, plus a small `SyncClient` interface so tests can use an in-memory fake.
  - `outbox.ts`: the record of unsent changes (`markDirty`, `clearOutboxEntry`, `countPendingChanges`, `clearOutbox`), saved on the device under `fitwizard-sync-outbox` so it survives restarts.
  - `registry.ts`: `registerCollection`.
  - `engine.ts`: `syncAll(userId)`. For each collection it pulls rows changed since the last pull (paged, 500 at a time), merges them per record, then pushes the outbox: upserts in batches of 200, and deletes sent as tombstones.
    - The pull position is kept per user, and only moves forward after a successful pull.
    - One collection failing doesn't stop the others.
    - Overlapping calls share one run.
  - `status.ts`: `useSyncStatus()` (signed-out → offline → saving → error → synced) and a pure `deriveSyncStatus()`.
  - `index.ts`: the public API.
- **Nothing calls `syncAll` yet.** The triggers come on Day 6, so app behaviour is unchanged.
- **`src/lib/offlineSave.ts` and its test deleted.** It held the queue only in memory and nothing used it; `outbox.ts` replaces it. Lane D's keep-list is updated.
- **`clearLocalUserData`** now also erases the outbox (in memory and on the device) and the pull positions.
- **Three "Wisdom AI" badges removed** (DEBT-046): `exercise_scientist`, `programming_nerd`, `wisdom_master`. Nobody can earn them, because the Wisdom chat isn't part of the app, and they mentioned AI. Saved data that still lists them is cleaned on load, since unknown badge ids are dropped.

## How it was verified
- **13 engine tests** against an in-memory fake database whose clock sets `updated_at` like the real trigger does:
  - first pull into an empty device
  - local-only push
  - newer-wins in both directions
  - remote tombstone removes the local item
  - local delete is pushed as a tombstone, not a hard delete
  - failed push stays in the outbox and succeeds on the next sync
  - unsent changes survive a restart
  - one failing collection doesn't stop the others
  - the cursor advances only after a successful pull
  - a different account starts fresh
  - overlapping calls share one run
  - sync-status precedence
- **Checked that the tests catch real bugs.** I broke the engine three ways (ignore tombstones; remote always wins; hard delete instead of tombstone), and each break made a test fail. The engine was restored from a backup and checked byte for byte.
- The erase test now also checks that the outbox and cursor are cleared.

## Review findings fixed (automated review on the PR)
1. **Unsent changes could be lost after a restart.** If the app restarted with unsent changes and the user changed something before the first sync, the new save replaced the saved outbox. Saving now loads and merges the saved outbox first.
2. **Deletes on one-row-per-user tables (`nutrition_settings`, `user_state`) were never sent.** The entry was cleared without updating the server, so the row stayed live. The delete is now sent filtered on `user_id` alone.

Each has a regression test, and both tests fail without the fix.
