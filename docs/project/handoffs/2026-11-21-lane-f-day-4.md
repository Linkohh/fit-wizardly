## What changed
- **`src/lib/account/deleteAccount.ts` (new, contract #4 client):** `deleteAccount(): Promise<{ error: Error | null }>`.
  - `POST {VITE_SUPABASE_URL}/functions/v1/delete-account` with `Authorization: Bearer <access token>` and `apikey`, no body. It takes the token from `supabase.auth.getSession()` and falls back to `authStore.session`.
  - On `204` it runs `await clearLocalUserData()` (contract #2), then `useAuthStore.getState().signOut()`. If either local step throws it still reports success, because the account is already gone.
  - On `401`, `500`, a network failure, no session, or demo mode it returns a `DeleteAccountError` (with `status`) and leaves the device data and session alone.
  - It doesn't navigate. The UI does that.
- **`src/components/account/AccountDeletionSection.tsx` (new):** the account block on Profile → Details.
  - **Signed in:** a destructive "Delete account" button opens an `AlertDialog`. The confirm button stays disabled until the user types exactly `DELETE`, and shows "Deleting…" while the request runs. Cancel and closing are blocked during that time. If it fails, an inline `role="alert"` message and a toast appear, and the button changes to "Try again". On success it shows a toast and goes to `/`.
  - **Guest (or demo mode with no Supabase):** "Erase data on this device", with the same type-DELETE pattern, calling `clearLocalUserData()`.
  - A "Download your data first" link under both runs the existing export.
  - The success toast reuses the toast id `fitwizard-data-kept-on-device`, so it replaces the "Signed out. Your training data stays on this device." toast that `signOut()` shows. That toast would be untrue after deletion.
- **`src/pages/Profile.tsx`:** the commented-out Delete Account button is replaced by `<AccountDeletionSection>`. `handleExportData` now calls `downloadUserDataExport()` (same toasts and file name), and three unused store imports plus `Trash2` are gone.
- **`src/lib/dataExport.ts`, export v3 (closes DEBT-059):**
  - `USER_DATA_EXPORT_VERSION = 3`. Every v2 key is unchanged: `settings`, `planHistory`, `workoutLogs`, `personalRecords`, `readinessLogs`, `nutrition.*`, `bodyMeasurements`.
  - New keys: `currentPlan`, `activeWorkout`, `trainingPreferences` (current week and unit), `achievements`, `customExercises`, `exercisePreferences` (favourites, collections, filter presets, recently viewed), `wizardDraft`, `onboarding`, `consent` (`consentGivenAt`, `analytics`, `nutritionLookup`), and `account` (email and Supabase `profiles` row, or nulls for guests).
  - `collectUserDataExportSources()` reads the live stores. Achievements, wizard and onboarding are exported through each store's own `partialize`, so the export matches what is saved on the device.
  - `EXPORT_SECTIONS_BY_STORE` maps each of the 9 `USER_DATA_STORE_NAMES` to its export keys. The test fails if a store is added to `clearLocalUserData` without an export section.
  - `downloadUserDataExport()` moved the Blob download code out of Profile.
- **Locales:** a new `account.*` namespace (18 keys) in `en`, `es`, `de` and `pt`. It's inserted as text directly before its alphabetical neighbour `achievements` in each file, not at the end, and no parser was used. All four are translated, so `localeGaps.json` is unchanged.
- **Tests:**
  - `deleteAccount.test.ts` (9 tests, mocked `fetch`): request shape, 204 clears then signs out, local failure after 204, 500, 401, network error, no session, store-session fallback, demo mode.
  - `AccountDeletionSection.test.tsx` (7 tests): disabled until exactly `DELETE`, loading state, success toast and redirect, failure then retry, export link, guest erase success and failure, demo mode uses guest erase.
  - `dataExport.test.ts` (10 tests): v2 keys kept, v3 sections, every store mapped and collected, consent flags, account.
