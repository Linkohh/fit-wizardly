## What changed
- **Wizard Enter key (DEBT-025)**, `src/pages/Wizard.tsx` (the window `keydown` handler only):
  - Ignores events that are already `defaultPrevented`. The muscle control (`MusclePath.tsx:294`) already calls `preventDefault()` on Enter/Space, so no MCL change was needed.
  - Form fields (`input`, `textarea`, `select`, `contenteditable`) keep every key, as before (`select` and `contenteditable` are new).
  - Enter on a focused `button`, `a[href]`, `[role="button"]`, anything inside an `svg` (the muscle canvas), or `[data-wizard-keys="off"]` belongs to that control and no longer advances the wizard. Escape on those still goes back a step, as before.
  - This also fixes a second case of the same bug: Enter on a focused wizard button (for example the "Full Gym" preset) activated the button **and** advanced the step.
- **New spec** `playwright/wizard.enter-key.spec.ts`: Enter on the background advances; Enter on a focused preset button doesn't change the step; Enter on a focused muscle selects it (`aria-pressed="true"`) and the step stays at 4; Enter on the background then advances to 5. Checked against the old handler: it fails there (at the preset-button step).
- **SetLogger keyboard (Lane H #83 carry-over)**, `src/components/logging/SetLogger.tsx`: calls `useKeyboard()` once at the top. While the native keyboard is open, the set card gets `paddingBottom: height`, so "Complete Set" can be scrolled clear of the keyboard. On the web `isOpen` stays false and nothing changes.
  - Tests in `src/components/logging/__tests__/SetLogger.test.tsx`: the hook is mounted with no padding while closed, and the card is padded by the keyboard height while open.
- **DEBT-106 allow-list removal**, `playwright/lifter-loop.spec.ts`: removed `'wizard:label-content-name-mismatch'` from `KNOWN_AXE_FINDINGS`. The stepper buttons pass now, but the same rule still fires on a **different** element, the Limitations step cards (`ConstraintsStep.tsx`). I added `KNOWN_AXE_ELEMENT_FINDINGS`, a per-element allowance that matches only when every failing node is one of those cards (markup contains `focus-visible:ring-warning`). A stepper regression, or the rule firing on any other wizard element, still fails the spec. Findings now carry `allHtml` (every failing node) for that check.
- **Theme fade (#85):** none of my tests change the theme, so no `armThemeSyncProbe`-style wait was needed.
